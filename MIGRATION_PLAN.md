# План миграции на модульную архитектуру

## 🎯 Цель
Безопасная миграция продакшн бота на модульную архитектуру без потери данных.

## ⚠️ Критически важно
- **Сохранить все датасеты** за 24 часа работы
- **Не потерять ни одного файла** с данными
- **Бот должен просто перезапуститься** и продолжить работу
- **Консерватор должен продолжить работу** без перерыва

---

## 📋 План миграции

### Этап 1: Подготовка (перед миграцией)

1. **Проверка текущего состояния**
   ```bash
   # Проверить что бот работает
   pm2 status
   
   # Проверить последние файлы
   ls -lth storage/trades/*.jsonl | head -5
   ls -lth storage/analytics/*.jsonl | head -5
   ```

2. **Создание резервной копии**
   - Автоматически создается скриптом миграции
   - Все данные копируются в `backup/migration_YYYYMMDD_HHMMSS/`

### Этап 2: Миграция данных

**Автоматически выполняется скриптом `scripts/migrate_to_modular.py`:**

1. **Резервное копирование**
   - Копирует `storage/` → `backup/migration_*/storage/`
   - Копирует `logs/` → `backup/migration_*/logs/`

2. **Миграция файлов**
   - `storage/trades/*.jsonl` → `storage/conservative/trades/*.jsonl`
   - `storage/analytics/*.jsonl` → `storage/conservative/analytics/*.jsonl`
   - **Старые файлы остаются на месте** (не удаляются)

3. **Проверка целостности**
   - Сравнивает размеры файлов
   - Проверяет что все файлы скопированы

4. **Генерация отчета**
   - Создает `backup/migration_*/migration_report.json`

### Этап 3: Обновление кода

1. **Обновление репозитория**
   ```bash
   cd /var/www/Sentinel
   git pull origin main  # или ваша ветка
   ```

2. **Проверка .env**
   - Убедиться что `ENABLE_CONSERVATIVE_MODULE=true`
   - Добавить если отсутствует

### Этап 4: Перезапуск

**Используется скрипт `scripts/safe_restart.sh`:**

1. **Остановка бота**
   ```bash
   pm2 stop sentinel
   ```

2. **Запуск миграции**
   ```bash
   ./scripts/safe_restart.sh
   ```

3. **Автоматическая проверка**
   - Проверяет что данные мигрированы
   - Запускает бота
   - Мониторит 30 секунд

## 🚀 Выполнение миграции

### Вариант 1: Автоматический (рекомендуется)

```bash
cd /var/www/Sentinel
sudo ./scripts/safe_restart.sh
```

Скрипт автоматически:
1. Проверит статус бота
2. Создаст резервную копию
3. Мигрирует данные
4. Проверит целостность
5. Перезапустит бота
6. Проверит что все работает

### Вариант 2: Ручной (если нужен больший контроль)

```bash
# 1. Остановить бота
pm2 stop sentinel

# 2. Запустить миграцию
cd /var/www/Sentinel
source venv/bin/activate
python3 scripts/migrate_to_modular.py

# 3. Проверить результат
ls -la storage/conservative/trades/
ls -la storage/conservative/analytics/

# 4. Обновить .env (если нужно)
echo "ENABLE_CONSERVATIVE_MODULE=true" >> .env

# 5. Запустить бота
pm2 restart ecosystem.config.js

# 6. Проверить логи
pm2 logs sentinel
```

## ✅ Проверка после миграции

### 1. Проверить что бот работает
```bash
pm2 status
pm2 logs sentinel --lines 20
```

### 2. Проверить что данные на месте
```bash
# Старые файлы (должны остаться)
ls -la storage/trades/*.jsonl

# Новые файлы (должны быть скопированы)
ls -la storage/conservative/trades/*.jsonl
ls -la storage/conservative/analytics/*.jsonl
```

### 3. Проверить что новые файлы создаются
```bash
# Подождать несколько минут и проверить
watch -n 5 'ls -lth storage/conservative/trades/ | head -5'
```

### 4. Проверить логи модуля
```bash
# Должны быть логи о запуске консерватора
grep "Conservative module" logs/sentinel_*.log | tail -10
```

## 🔄 Откат (если что-то пошло не так)

### Если миграция не удалась:

1. **Восстановить из бэкапа**
   ```bash
   cd /var/www/Sentinel
   BACKUP_DIR=$(ls -td backup/migration_* | head -1)
   cp -r $BACKUP_DIR/storage/* storage/
   ```

2. **Вернуться к старому коду**
   ```bash
   git checkout <old-commit-hash>
   ```

3. **Перезапустить бота**
   ```bash
   pm2 restart ecosystem.config.js
   ```

## 📊 Структура данных

### До миграции:
```
storage/
├── trades/
│   └── trades_2025-12-25.jsonl
└── analytics/
    ├── ai_decisions_2025-12-25.jsonl
    └── market_conditions_2025-12-25.jsonl
```

### После миграции:
```
storage/
├── conservative/          # Новое расположение
│   ├── trades/
│   │   └── trades_2025-12-25.jsonl  # Мигрировано
│   └── analytics/
│       ├── ai_decisions_2025-12-25.jsonl  # Мигрировано
│       └── market_conditions_2025-12-25.jsonl  # Мигрировано
├── trades/               # Старое (остается для совместимости)
│   └── trades_2025-12-25.jsonl
└── analytics/            # Старое (остается для совместимости)
    └── ...
```

**Важно:** Старые файлы **НЕ удаляются** автоматически. Их можно удалить вручную после проверки.

## ⏱️ Время миграции

- **Резервное копирование:** ~1-2 минуты (зависит от размера данных)
- **Миграция файлов:** ~30 секунд
- **Перезапуск бота:** ~10 секунд
- **Общее время:** ~2-3 минуты

**Простой бота:** Минимальный (только время перезапуска)
