# 📁 Стратегия хранения данных для калибровки

## 🎯 Цель
Оптимизировать хранение торговых данных для эффективного обучения Grok и удобного анализа.

## 💡 Предлагаемое решение: Гибридный подход

### Структура файлов:
```
storage/
├── trades/
│   ├── trades_2024-12-24.jsonl  # Ежедневные файлы
│   ├── trades_2024-12-25.jsonl
│   └── trades_2024-12-26.jsonl
├── trades_index.json            # Индекс файлов (метаданные)
└── trades_current.jsonl         # Текущий день (для записи)
```

### Преимущества:
1. **Ежедневные файлы** - для анализа и архивации
2. **Индекс файлов** - быстрый поиск и доступ
3. **Текущий файл** - быстрая запись без поиска нужного файла
4. **Автоматическая ротация** - в полночь создается новый файл

### Логика работы:

#### Запись:
- Все новые сделки пишутся в `trades_current.jsonl`
- В полночь (UTC) файл переименовывается в `trades_YYYY-MM-DD.jsonl`
- Создается новый `trades_current.jsonl`
- Обновляется индекс

#### Чтение для Grok:
- `get_recent_trades(limit=5)` читает из:
  1. `trades_current.jsonl` (если есть)
  2. Последние N дней из `trades/` (по индексу)
  3. Объединяет и сортирует по времени
  4. Возвращает последние `limit` закрытых сделок

#### Анализ:
- Можно анализировать по дням
- Можно объединять несколько дней
- Легко удалять старые данные

## 🔄 Альтернатива: Простой подход

Если гибрид кажется сложным, можно упростить:

### Вариант 1: Только ежедневные файлы
- Всегда пишем в `trades_YYYY-MM-DD.jsonl`
- При чтении ищем файл текущего дня
- Если не найден - создаем новый

### Вариант 2: Еженедельные файлы
- Один файл на неделю
- Меньше файлов, но все еще управляемый размер

## 📊 Рекомендация

**Для фазы калибровки (2 недели):**
✅ **Ежедневные файлы** - оптимально
- Не будет слишком много файлов (14 файлов)
- Каждый файл будет небольшой
- Легко анализировать по дням
- Grok сможет читать полные файлы

**Для продакшена (долгосрочно):**
✅ **Гибридный подход** с ротацией
- Автоматическая ротация
- Индекс для быстрого доступа
- Возможность архивации старых данных

## ⚠️ Важные моменты

1. **Контекст для Grok**: При чтении истории нужно объединять данные из нескольких дней
2. **Сортировка**: Важно сортировать по времени, а не по файлам
3. **Открытые позиции**: Могут быть в текущем файле, нужно учитывать при чтении
4. **Производительность**: Чтение нескольких маленьких файлов быстрее одного большого
